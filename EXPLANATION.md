# Пояснение реализации

### №1. Что такое Serializer и ModelSerializer? В чём разница?

Serializer преобразует данные Python в формат API (обычно JSON) и обратно, а также проверяет входящие данные. Все поля, правила проверки и сохранение можно описать вручную. ModelSerializer делает то же самое, но строит часть полей и проверок автоматически по модели Django. В этом проекте ModelSerializer удобен для комнат и профиля, а отдельная логика бронирования нужна потому, что при создании надо проверить пересечения и списать деньги.

### №2. Для чего нужны mixins?

Mixins — небольшие готовые части представлений DRF для типовых действий: список, создание, просмотр одного объекта, изменение или удаление. Их можно сочетать, оставляя только нужные операции. Например, в API бронирований включены список, создание и просмотр, но обычные изменение и удаление недоступны: вместо удаления используется контролируемая отмена.

### №3. Как запретить пользователю просматривать чужие бронирования?

Нужно ограничить queryset текущим пользователем: `Booking.objects.filter(user=request.user)`. Тогда чужая запись отсутствует даже при запросе её ID, и API отвечает 404. В проекте эта проверка используется одновременно для списка и получения отдельного бронирования.

### №4. В чём разница между GET, POST, PUT, PATCH и DELETE?

- `GET` читает данные и не должен менять их.
- `POST` создаёт объект или запускает действие, например отмену.
- `PUT` заменяет объект целиком.
- `PATCH` меняет только переданные поля.
- `DELETE` удаляет объект.

### №5. Как запретить клиенту изменять определённые поля через API?

Не включать их во входной сериализатор либо объявить `read_only=True`. Например, баланс в сериализаторе профиля доступен для чтения, но не принимается на изменение. Цена и статус бронирования также не приходят от пользователя: сервер рассчитывает цену, а статусом управляют отдельные действия.

### №6. Для чего используется кэширование?

Кэш хранит результат дорогого или часто повторяемого запроса, чтобы быстрее отвечать и реже обращаться к базе. В проекте публичный список комнат кэшируется на 60 секунд; после изменения комнат версия ключа меняется, поэтому следующий запрос получает свежие данные.

### №7. Для чего нужна документация Swagger?

Swagger показывает маршруты API, методы, параметры, схемы данных и ответы в интерактивном виде. Через страницу документации можно изучать API и отправлять запросы, не создавая отдельный клиент.
